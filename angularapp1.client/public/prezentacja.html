System kluczykowy

Aplikacja webowa do ewidencji zabierania i oddawania kluczy samochodowych - z rolami Admin / Pracownik, skanerem QR i historią zdarzeń.

Stack: Angular · ASP.NET Core · PostgreSQL Czas: ok. 5–10 min

Problem

Po co powstała aplikacja?

Potrzeba biznesowa

Kontrola, kto ma który klucz firmowego auta - bez papierowych list i domysłów.

Cel systemu

Szybkie zabranie / oddanie klucza (QR), aktualny status floty i historia dla administratora.

Użytkownicy

Pracownik - skaner i akcje. Administrator - rejestr, QR, historia, zagubione.

Architektura

Co zostało użyte?

Frontend

  • Angular 21 + TypeScript
  • RxJS, routing, guards
  • SCSS, motyw jasny/ciemny
  • html5-qrcode, qrcode, jszip

Backend i dane

  • ASP.NET Core (REST API)
  • PostgreSQL + EF Core
  • JWT + role (Admin / Pracownik)
  • Migracje, logi historii
SPA REST API JWT QR Git / GitHub

Funkcje - pracownik

Panel pracownika

Zabierz / Oddaj

Dwie ścieżki: zabranie klucza albo zwrot do szafki.

Skaner QR

Kamera lub ręczne wpisanie kodu z etykiety.

Przejęcie nieoddanego

Jeśli auto jest nadal „w użyciu”, system prosi o potwierdzenie odznaczenia i zabrania.

Prywatność

Pracownik nie widzi, kto aktualnie posiada klucz.

Funkcje - administrator

Panel administratora

Rejestr floty

  • Wolne / w użyciu / zagubione
  • Filtry i wyszukiwanie
  • Statystyki na kartach

Klucze

  • Oryginalny, zapasowy lub oba
  • Edycja tablic
  • Notatki, zagubione

QR i historia

  • Etykiety QR (druk)
  • ZIP dla całej floty
  • Historia ~30 dni

Logika domenowa

Cykl życia klucza

1
FREE - wolny Klucz w szafce, gotowy do zabrania.
2
IN_USE - w użyciu Przypisany do użytkownika (TakenAt / HeldBy), widoczny w rejestrze.
3
Zwrot lub przejęcie Oddanie → FREE. Przejęcie nieoddanego → wymuszone potwierdzenie + log.
4
LOST - zagubiony Admin oznacza klucz; po odnalezieniu wraca do obiegu.

Demo - co pokazać na żywo

Scenariusz prezentacji

1
Logowanie Admin i pracownik - różne panele po roli.
2
Admin: dodaj klucz + QR Oryginał / zapas / oba → wygeneruj etykietę.
3
Pracownik: Zabierz klucz Skan lub kod ręczny → potwierdzenie zabrania.
4
Przejęcie i historia Drugi użytkownik przy nieoddanym aucie + podgląd historii u admina.

Bezpieczeństwo i jakość

Ważne decyzje techniczne

Autoryzacja

JWT w API, Angular guards, rozdział endpointów Admin vs Pracownik.

Dane wrażliwe

Maskowanie posiadacza klucza dla pracowników w odpowiedzi API.

Trwałość

PostgreSQL, migracje EF, logi TAKE/RETURN w historii.

UX

Motyw light/dark z zapisem wyboru, UI pod telefon (skaner).

Podsumowanie

Efekt końcowy

Pełnostackowa aplikacja do zarządzania kluczami floty: Angular + ASP.NET Core + PostgreSQL. Pracownicy operują skanerem QR, administrator prowadzi rejestr, generuje etykiety i analizuje historię.
Wynik: działający system z rolami, QR, historią i motywem
